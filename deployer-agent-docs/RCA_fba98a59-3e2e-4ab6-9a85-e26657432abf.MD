# RCA — "Production not showing latest changes" (bridgebot.tech)

## Problem statement
User deployed latest changes (API Key Analytics columns + External API Calls section, Bot Logo upload, custom welcome message / default-open widget). Preview (rag-search-dev.preview.emergentagent.com) shows them; production (bridgebot.tech) reportedly does not.

## Verdict
**Production IS serving the latest deploy on both domains. The new code is live.** The symptom is a stale client-side/browser (or edge) cache on the user's machine — not a failed/stale deploy.

## Evidence
1. **Pipeline green & promoted** — Run `fba98a59-3e2e-4ab6-9a85-e26657432abf` (redeploy) succeeded at 2026-11-11T07:34:42Z and is the active run. `build_image` succeeded; `frontend-build-push` uploaded fresh artifacts to R2 (`deployer-frontend-artifacts/rag-search-dev/fba98a59.../build/`, bundle `main.58d326c4.js`). Frontend type = cloudflare (served from R2).

2. **Pulled source contained all 3 features** (verified in eph sandbox on this run's source):
   - `frontend/src/pages/ApiKeyAnalytics.js` → contains "External API Calls"
   - `frontend/src/pages/ChatWidget.js`, `EmbedCode.js` → welcome message logic
   - `frontend/src/pages/BotSettings.js`, `ChatWidget.js` → logo upload logic

3. **Live production bundle contains the features** — fetched the actual served JS:
   - `https://rag-search-dev.emergent.host/static/js/main.58d326c4.js` → contains "External API Calls" ✅, "defaultOpen" ✅, "Bot Logo" ✅
   - `https://bridgebot.tech/static/js/main.58d326c4.js` → identical bundle, same features ✅
   - `https://bridgebot.tech/` index.html → references the NEW `main.58d326c4.js` (not a stale hash)
   (`welcomeMessage`/`logoUrl` literal strings absent only because they're minified/renamed — feature code confirmed present.)

## Root cause
No deploy defect. Both the default domain and the custom domain serve the new build with all three features. The user is viewing a locally/edge-cached old version (cached `index.html` + old JS bundle).

## Suggested fix
- **User (test_and_verify):** Hard refresh (Cmd/Ctrl+Shift+R) or open bridgebot.tech in an incognito/private window on the affected device. Confirm the three features now appear. If a corporate proxy/CDN sits in front, purge its cache too.
- If features still appear missing after a clean incognito load, the issue would be a runtime/backend one (e.g. logo-upload object-storage call or analytics API failing at runtime) rather than the deploy — capture the failing request in DevTools Network tab and re-report.

## Not the cause (ruled out)
- Build/deploy failure — pipeline fully green.
- Stale source pull — pulled source had the new code.
- Custom-domain serving old bundle — bridgebot.tech serves the new bundle identical to the default URL.
