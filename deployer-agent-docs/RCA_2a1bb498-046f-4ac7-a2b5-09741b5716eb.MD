## Root cause
Production email configuration is correct (key present; From resolves to the verified `noreply@bitbotpro.io`). The reported failure **cannot be reproduced or confirmed from logs because the email flow has not actually been exercised on the current production pods** since the 09:50Z redeploy. There is no error to find because no send was attempted.

`admin@bitbotpro.io` DOES exist in the prod DB and `is_verified:true` (role superadmin), so `forgot_password` (server.py:2668) would attempt a send for it — note it returns the generic "If that email is registered..." message regardless, and only sends when the user exists AND is verified. For an unregistered/unverified address it silently no-ops with no log.

## Latent code bug (separate from the reported issue)
`backend/server.py:5959` — the Discord bot-invite email hardcodes the OLD domain:
`"from": "BitBot Pro <noreply@bridgebot.tech>"`
All other email paths use `FROM_EMAIL` (bitbotpro.io). If `bridgebot.tech` is not verified in the current Resend account, this specific email type will fail with a Resend 403 "domain not verified". Should be changed to use `FROM_EMAIL`.
