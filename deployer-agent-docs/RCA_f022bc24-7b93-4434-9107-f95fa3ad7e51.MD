# RCA — Discord bot "won't make live API calls" in production (bridgebot.tech)

## Problem statement
Production Discord bot replies "I don't have the ability to make live API calls myself — I can only help you build the correct request" and suggests `curl` with placeholder `YOUR_KEY`, when asked "can you query a transaction for me". Preview returns the correct reply: "Sure! I'd be happy to help you query a transaction. Please provide me with the transaction hash."

## Root cause (confirmed)
The `__NO_KB__` fix and the data are both fine. The failing path is the **final answer prompt** when the user has NOT yet supplied an identifier (hash/address):

- Router returns `action: none` → `_try_api_query` returns `None` → `api_context = ""`.
- The answer is produced by `build_system_prompt(...)`. The ONLY place it tells the LLM it can make live API calls (and to "ask them for the specific identifier (hash, address...) if they haven't provided one, and the system will make the API call for you") is at `server.py:612`:
  ```python
  elif bot_config.get("api_query_enabled"):
      parts.append("IMPORTANT — LIVE API CAPABILITY: ...")
  ```
- This hint is gated SOLELY on the legacy per-bot flag `bot_config.api_query_enabled`. The API Tester instance (`fc19c65d`) is configured through the NEW `api_integrations` collection, and its `bot_config` document has **no `api_query_enabled` field** (verified in DB). So the hint is omitted.
- `has_api_integrations` IS computed for the bail-out, but it is **never passed into `build_system_prompt`** (call sites 1429, 1773, 2458, 2893 omit it). So when `api_context` is empty, the LLM is never told it can call APIs and defaults to "I can't make live API calls — here's a curl with YOUR_KEY."

In short: the migration to the new `api_integrations` model was applied to the `__NO_KB__` bail-out and to the `api_context` injection, but NOT to the "offer to make the call / ask for the identifier" capability hint, which still keys off the legacy `api_query_enabled` flag.

### Why preview works but prod doesn't
Preview's reply ("Please provide me with the transaction hash") is exactly the output of the LIVE API CAPABILITY hint. Since the deployed code is identical, the difference is data: the preview DB's `bot_config` for the tested instance has `api_query_enabled=true` (legacy flag set), whereas production's API Tester `bot_config` does not. (Preview internals were not directly inspected — this is inferred from the identical code + the known gate.)

## Recommended fix
**Primary — Code (E1), requires redeploy:** In `build_system_prompt`, emit the LIVE API CAPABILITY hint whenever the instance has enabled API integrations, not only when the legacy `api_query_enabled` flag is set. Concretely, pass the already-computed `has_api_integrations` into `build_system_prompt` and change the gate at line 612 from `elif bot_config.get("api_query_enabled"):` to also trigger on `has_api_integrations`. This completes the same migration already done for the `__NO_KB__` bail.

**Fast workaround — User (data):** Set `api_query_enabled: true` on the API Tester instance's bot settings so the deployed code emits the capability hint. (This is the field the preview DB appears to already have. If the app UI doesn't expose this toggle for new-style integrations, use the Code fix.)
