# RCA — Preview backend cannot connect to MongoDB

## Problem statement
Preview backend is stuck on startup because `backend/.env` `MONGO_URL` holds an invalid/masked password. The `.env` had been overridden with a user-owned Atlas cluster that is now DNS-dead. An attempt to replace it with the Emergent-managed string (`customer-apps.i9ml59.mongodb.net`, db `test_database`) failed because the security system masked the password.

## What I verified
- Production deployment `rag-search-dev` is **active and healthy** (active run `fa3c1c96-...`, live at https://rag-search-dev.emergent.host).
- The **Emergent-managed / shared MongoDB is reachable and fine**: using the managed connection string (resolved server-side, never exposed), `list_collections` returned 11 collections on db `rag-search-dev-test_database` (users, conversations, bot_config, knowledge_sources, etc.).
  - => The database is NOT down. Only the **preview `.env` override** is broken (it still points at the user's dead Atlas cluster).

## Root cause
Two layers:
1. The preview `backend/.env` `MONGO_URL` was manually overridden with a user Atlas cluster that now fails DNS resolution — so the backend cannot connect on boot.
2. The fix was blocked because the real managed password is **masked by design**. Credential values are never written to plaintext `.env` by the security tooling, and no agent (including me) can read or restore that masked value.

## Why I can't fix it directly
- I have no tool to edit the preview environment's `backend/.env` (my tools target the production deployment).
- Secret values (the Mongo password) are never exposed to me — this masking is an intentional security control I will not bypass.

## Important: production is unaffected
In production, `MONGO_URL` is a SYSTEM key that is regenerated from production state on every deploy. This preview `.env` problem does not affect the live app and will not carry into a deploy.

## Recommended fixes
1. **Platform / Support (primary):** The preview environment's platform-managed `MONGO_URL` must be **re-injected/restored from the managed credential source**, not hand-pasted. Because the password is masked, this requires the Emergent platform credential system. File a support ticket quoting deployment id `53da33a5-f822-4c89-9d0e-a591416dc935` and job id `79392e84-e28d-44f5-85af-9a29e748f981`.
2. **Code (E1):** Remove the stale dead-Atlas override from `backend/.env` so the preview environment's platform-injected managed `MONGO_URL` can take effect, rather than trying to paste a masked value. (If the preview env injects `MONGO_URL` at the process level, clearing the override is often enough to restore connectivity.)

Do NOT attempt to resolve this by typing the masked password into `.env` — that value cannot be obtained and the masking is a deliberate security control.
